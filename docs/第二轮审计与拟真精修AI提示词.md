日期：2026-09-29。审计对象：当前 STELLARAIL Studio v2，项目 `E:\Aclaw文件\机械键盘配置器`。

## 1. 本轮结论

**目前功能已从单型号演示扩展成多产品配置器，但视觉仍明显呈现“基础几何体装配”的效果。下一轮最值得投入的是键帽造型、可解释的装配结构、材质反射和产品摄影式展示，而不是继续增加配列数量或配色按钮。**

现有截图中的方块感与源码一致：每颗键帽依旧由两个直角长方体组成；底壳虽然增加了圆角和倒角，却仍是实心挤出块；定位板没有轴孔，USB-C 只是附着在壳体上的深色方块，半透明外壳靠 opacity 实现。材质与灯光没有形成能显示曲面、加工边缘和材料差异的完整体系。

本轮只增加这份审计与执行提示词，不改产品代码。相较第一轮，本轮重点是深化已完成的系统，而非重新要求从零增加六配列。

### 两个容易被功能清单掩盖的结构问题

**装配不等于把平板叠起来。** 当前 PCB 中心高度为 0.5、厚 0.06，内托中心同为 0.5、厚 0.1；二者在主要平面区域存在体积交叠。轴壳中心 0.74、厚 0.2，底部 0.64；定位板中心 0.62、厚 0.1，顶部 0.67，却没有开孔，装配区间重叠。拆解时虽能分开，合拢并没有形成可信的结构。

**旋钮占位验证不等于旋钮几何验证。** 数据中的 `knob.r=0.62` 未被模型采用，模型底座最大半径 0.72、旋钮半径最大 0.6，而布局测试仅检查 1×1u 方格。这不能证明与邻键的实体间隙安全。当前正下方 Home 的中心距为 1u，键帽底座半深 0.43，加上旋钮半径已超过 1u，存在平面侵入，需要结合不同高度与全按压行程检查三维碰撞。

### 资源管理：精修前必须解决的隐患

`disposeBoard()` 与“共享资源”的实际所有权不一致，不能直接接受旧报告的“资源有界稳定”结论：

1. 每次 `buildBoard()` 都新建脚垫、轴壳、轴心、稳定器几何，再覆盖 `geoCache._feet/_housing/_stem/_stabStem`；这些网格未设 `ownGeo`，释放路径不覆盖它们。复古 LED 同类问题。**源码存在未显式释放的路径；GPU 增长量尚未实测。**
2. 字符材质标记 `ownMat=true`，释放材质时也释放 `map`，但 map 同时被 `texCache` 缓存跨型号共享。之后可能重建 GPU 资源，产生重复上传；不能称为清晰的共享缓存。
3. 加入高细分键帽、环境贴图和透射以后，这类问题会放大。先明确资源所有权，再进行 50 次混合系列切换、对比和导出的压力测试，分别报告预热前后与稳定期数据。

## 3. 对现有验收结论的修订建议

旧报告证明了一部分功能路径可用，但还不足以证明产品展示精修完成。

- “六配列布局通过”本轮重新核验成立；它只验证二维键位，不验证键帽曲面、轴孔、旋钮实体、接触或材质真实性。
- “移动端通过”需要重新打开：截图 12 明确出现文案压住模型及右侧截断；源码还隐藏核心选型入口。不能仅以上下堆叠、能滚动作为通过标准。
- “资源稳定”须补上述所有权路径核查和新的混合场景测试；不据单张 HUD 截图判定无泄漏。
- 半透明材质已经在旧报告中明确为概念示意，本轮应将其列为主要品质升级目标，而不是说它已经具备写实效果。

## 4. 升级路线：先建立品质样板，再推广

### 阶段 A：一个型号做出明显的质量差异

固定 K65、奶霜键帽、曜石黑铝壳、同一视角与画面占比，完成键帽、外壳、字符、光照、接触关系。另准备同一型号的浅灰无纹理诊断图，排除用配色和灯光掩盖几何缺陷。

样板验收必须能看到：连续收分的键帽轮廓、真正的顶部凹面、窄而稳定的倒角高光、可阅读的字符、暗壳轮廓、真实装配间隙与脚垫支撑。未达成前，不扩散到全部型号。

### 阶段 B：装配结构与外观系列

完成五层装配逻辑、孔位、长键稳定器、接口和紧固件，处理四个系列的结构差异；半透明款和旋钮款在本阶段单独验收。再将公共几何与材质体系推广到六配列和旋钮变体。

### 阶段 C：产品展示与探索

增加真正有用的品质相关功能：键帽轮廓选择、材质对照、可聚焦部件的近景、单键取帽、分层隔离、展示模式与高质量导出。优化移动端选型和取景。

本阶段不再扩展更多配列、支付、社区或复杂 RGB，避免功能范围再次挤占模型精修。

### 阶段 D：可比对的视觉验收

保留 v2 基线，在统一相机、视窗、模型占比、主题与背景下输出 v2/v3 对照。按“几何 → 材质 → 灯光 → UI → 性能”分层检查，不能以最后一张氛围图替代结构与交互验收。

### 任务原则

先读源码及 `docs/第二轮审计与拟真精修AI提示词.md`，备份当前 v2。只改源文件并通过现有构建生成 `index.html`，不要单独修改生成物。保留旧备份和已有文档。

继续交付可以双击离线使用的自包含 HTML；开发期可模块化，但模型、贴图、字体和渲染依赖须内嵌或本地程序生成。沿用 Three.js r160，除非升级有明确必要性并完成兼容回归。不要复制框架重写现有功能。

将目标设为“近看仍可信的原创键盘产品展示”，不要只增加圆角卡片、环境光、反射或配色。先修几何和装配，再调材质、光照与界面。所有实际产品参数都是原创设计值，不假冒真实厂商或真实制造验证。

### 一、建立统一尺寸与结构参数

- 保留布局坐标 u，明确 `1u=19.05mm` 仅作为本项目换算。定义毫米制零件参数并统一换算到渲染单位，禁止散落的魔法高度。
- 产品数据至少包含：键帽轮廓与行编号、壳体壁厚/边框/底板厚度、打字倾角、板厚、板与 PCB 间隙、轴心行程、稳定器类型与方向、脚垫、旋钮包络及接口位置。
- 修复当前 PCB 与内托、轴壳与无孔定位板交叠；每层应能解释如何装配、承托和固定。
- 外观尺寸从真实外壳几何计算，区分“外壳尺寸”和“键位区域”。复古铭牌同步当前型号与键数；1.5mm 等说明与模型厚度一致。
- 不把随机参数范围宣传为键盘行业标准。若采用具体键帽 profile 或轴体结构规范，使用一手资料并记录来源；原创近似款明确标为原创设计。

### 二、彻底重做键帽

这是本轮最高优先级。替换 `capBaseGeo/capTopGeo` 的双 BoxGeometry 方案。

实现连续闭合的参数化键帽网格：圆角矩形下缘、侧壁收分、顶部肩部过渡、浅凹顶面、连续法线与干净 UV。需要可控制的底部开口、壁厚和轴心安装位，用于取帽/拆解近景。别仅将两个方块改成两个圆角方块。

建议采用分层轮廓 loft 加顶部曲面网格，缓存键包含 w/h、profile、行号与质量档。顶面凹陷在边缘平滑回到肩部；侧壁收分、圆角和凹面分别可控；避免凹陷贯穿侧壁、法线接缝和薄片。

至少实现两种真实改变几何的轮廓：一套偏低的逐行雕刻式轮廓，一套偏高的复古球面凹顶轮廓。显示为原创轮廓，除非已验证，不冒用特定商品尺寸或兼容承诺。每种轮廓独立定义各行高度、倾角和凹面，而不是把整套键帽简单拉高。

覆盖 1u、1.25u、1.5u、1.75u、2u、2.25u、2.75u、6.25u 和数字区竖向 2u。长空格须有独立顶面设计和底部安装结构；横长键与竖长键不能用同一横向凹槽拉伸凑合。细节图中检查 F/J 定位凸点、裙边、凹面、边角和字样。

按键运动需与安装关系一致：键帽、运动轴心和稳定器活动件联动，轴壳及定位板保持固定。按压位移与所选轴体的设计行程一致，或明确标为视觉演示行程；最低点无穿板、邻键碰撞和字样脱离。拆解/取帽时定义哪些部件可交互。

### 三、字符精修

- 建立独立 `legend` 描述，区分物理 code、显示主字符、副字符与对齐规则；`N/`、`N+`、`⏎N` 等内部识别文本不应印在成品键帽上。
- 统一字体、字重、尺寸与留白；字母、数字双字符、导航缩写、修饰键符号分别排版，不把所有标签都居中缩成相同小块。
- 字符贴合曲面，使用顶面 UV 或贴合网格；如使用 decal，解决深度竞争、视角排序和倾斜后的表面距离。
- 字符与键帽接受协调光照，避免 BasicMaterial 带来的恒定亮度贴纸感；印刷不等于发光，不要用描边提高可读性。
- 正确声明颜色贴图色彩空间，法线/粗糙度等数据纹理不做 sRGB 转换。纹理分辨率、mipmap 和过滤按实际字号验证，避免近景锯齿与远景闪烁。
- 自定义改色后保证可读，但允许材质与光照引起合理明暗变化，不能要求 3D 像素与 CSS 色块完全相同。

### 四、外壳和内部结构达到近景可看

1. 建立上框、底壳内腔、壁厚、板件承托、支撑柱、螺丝位置和合理接缝。通过带孔轮廓/分件挤出等明确几何形成真实开口；避免每次切换执行昂贵的通用 CSG。
2. 定位板按键位生成轴孔与稳定器所需开口，孔位和轴体位置同源，不能在一整块实心板上摆轴体。
3. PCB 加入克制的焊盘、热插拔座、少量元件与丝印，优先实例化或烘焙；无需仿造可制造电路。标注为结构示意，不编造电气功能。
4. 轴体有可辨识的上盖、底座、十字轴心与卡扣，避免黑方块加白方柱。细节按观察距离加载，不必每颗轴都塞满不可见零件。
5. 根据宽度或高度与实际布局定义稳定器，支持空格、Shift、回车、数字区 Enter/+。钢丝应有弯折路径、插入位置和独立塑料座，不用一根横向长方体代替所有情况。
6. USB-C 做实际开口、内缘和舌片/接口轮廓；底面添加有装配逻辑的脚垫、螺丝孔和型号铭牌。壳体应有高光可读的倒角，但不能圆润到像软塑料玩具。
7. 用脚垫接触确定支撑高度，前后倾角通过一致的壳体/脚垫设计实现。默认桌面展示不应整盘悬浮；单独的悬浮展示模式须明确区分。

四系列共享必要基础，但保留真正不同的结构特征：极简款精密薄边，复古款有比例合理的较厚外框和双色分件，透明款呈现内腔与壁厚，旋钮款带真实加工细节和附件空间。

旋钮使用数据中统一的半径/高度参数，做倒角、顶面浅槽或细密加工纹、侧面滚花与轴座；在正常画面不产生摩尔纹。以真实几何包络校验与 Home 等邻键的距离，并验证全行程碰撞。不能继续用 1×1u 占位测试代替实体测试。

### 五、建立可信的材质与棚拍光照

先做一组灰卡及材质对照样本，固定曝光、白平衡和背景，再调全产品。禁止通过过曝、重 AO 或重泛光掩盖几何问题。

- 明确输出色彩空间、tone mapping 和曝光，按 r160 验证。可选择 ACESFilmic 作为起点，但不能将一个 toneMapping 开关当成写实完成。
- 引入 PMREM 预过滤环境反射：优先离线生成带大面积明暗分区的棚拍环境，或内嵌来源合规的 HDR。大软箱的反射形状用于显示键帽曲面和倒角，不是给表面加白色贴片。
- 若使用 RectAreaLight，核验版本及所需初始化依赖；不要假设它自动提供可用阴影。环境反射、直接光与投影分别设计，再统一校准。
- 塑料采用非金属响应与细腻粗糙度；微纹理尺度足够小，近看可辨、远看不脏不闪。不要给 ABS/PBT 统一加金属感。
- 阳极氧化铝与旋钮采用合理金属响应、细微加工方向性与粗糙度差异；如果使用复杂涂层近似，明确为视觉建模近似。
- 半透明壳体先有内外表面与真实厚度，再用 MeshPhysicalMaterial 的 transmission、thickness、ior、roughness、attenuation 等按版本校准。透射不能只降低 opacity；避免多层透明与内部零件排序错误。提供效果诚实的低质量档，并标明近似效果。
- 阴影与接触效果跟随装配/拆解/按压更新；AO 可加强缝隙，不得把浅色键帽染成灰泥或在悬浮层间留下固定黑块。
- 默认中性棚拍，额外提供暖色桌面与深色轮廓光场景；这些只改变展示，不污染用户的产品配色或尺寸数据。

### 六、展示交互为细节服务

增加“专注展示”模式，收起非必要侧栏并扩大模型；保留返回入口。默认不持续自动旋转，用户可自行开启，拍摄与对比时停止。

部件近景要真正以目标为相机焦点：键帽凹面、空格稳定器、旋钮、USB-C、底部。当前仅拉近整盘的“细节”视角不够。实现点击部件→名称/材质说明→平滑聚焦→一键回全景。

加入单颗键帽取下/放回、层隔离及可控拆解，帮助用户理解材料和装配。不能为提高展示感而破坏现有敲击、布局选择与方案状态。

移动端必须保留六配列和四系列的可达选择入口，可使用抽屉或紧凑选择器。将标题、价格/规格与 3D 舞台分开；根据真实可用矩形、Box3、当前视角和拆解包围盒求取景，而不是只根据屏幕宽度缩小字号。横竖屏切换后重算。

提供质量档位和高清 PNG 导出。交互画面与导出使用同一材质体系，导出时保持用户选定产品和明确约定的视角，正确处理输出比例、相机 aspect、恢复状态与透明背景。可高质量临时渲染，但不要将离线渲染图冒充实时预览质量。

### 七、资源管理与性能先修再扩展

修复现有资源生命周期：每次重建的新几何不能伪装成永不释放的共享缓存；共享字符纹理不由单键材质释放；私有材质/几何/贴图与环境资源分别管理。建立明确资源注册、复用与释放规则，避免重复 dispose 或遗漏。

保留实例化与按需渲染。高低档主要改变细分、阴影、贴图和透射成本，不删核心外观轮廓。真实测试 GPU 帧时间/交互 FPS、draw calls、triangles、geometry/texture 计数；报告分辨率、DPR、质量档和设备。不要把静止不渲染的 FPS 0 当性能异常，也不要因此宣称交互 60 FPS。

### 八、阶段门槛与不可省略的验收

按以下顺序完成，持续执行至交付；阶段门槛为内部质量自检，不需要每一步向用户要批准：

**A. 基线与诊断**：备份 v2、固定产品和视角，保存源文件哈希与配置；修复移动选型、尺寸/铭牌和资源所有权问题。

**B. K65 品质样板**：完成键帽、外壳、字符、灯光与接触。输出相同画面占比的前后对照与灰模图，近看确认不再是双层方块。

**C. 推广与结构**：扩展到全部配列、两套键帽轮廓和四系列，完成半透明、旋钮和长键装配。

**D. 展示与回归**：完成细节聚焦、取帽/层隔离、场景切换、移动适配、质量档和导出，回归原有配置功能。

验收矩阵至少包括：

| 验收项 | 必须提供的证据 |
| --- | --- |
| 键帽几何 | 1u、长空格、横向长键、竖向 2u 的顶/侧/斜视近景；曲面连续，无明显台阶与破面 |
| 行轮廓 | 两套轮廓的相同侧视对照；高度/倾角有设计依据，按压不碰邻键 |

| 材质 | 同灯光下浅塑料、深塑料、金属、半透明近景；透明款不能仅成为灰色影子 |
| 字符 | 字母、双字符、导航、长键与数字区标签可读；斜视不漂浮，缩远不闪烁 |

| 状态回归 | 切配列/材质/profile、保存/载入、JSON、对比、试键、取帽、拆解、导出与恢复互不破坏 |
| 资源 | 至少 50 次混合切换，包含透明/复古/旋钮、对比和导出；缓存预热后资源无持续无界增长 |

不得仅依据“已设置 roughness/已加倒角/测试脚本通过”判定精修成功。必须审阅实际截图并修复明显问题。浏览器限制或未验证的项写清楚，遵守工具策略，不绕过。已有截图属于历史证据，不能冒充本次构建截图。

## 6. 技术依据与版本注意

- 环境反射是标准 PBR 材质获得清晰材料表现的重要组成部分；官方建议为 MeshStandardMaterial 配置环境贴图。本项目当前缺少该环节。[Three.js MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html)
- 光学透射与普通透明度不同，使用 transmission 时官方要求 opacity 保持 1；物理材质增加每像素成本，因此需要质量档与实测。[Three.js MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)
- 彩色贴图应声明相应色彩空间；法线与粗糙度等非颜色数据不可按颜色贴图处理。[Three.js Color Management](https://threejs.org/manual/pages/color-management.html)

以上链接为当前官方文档，项目为 r160。实现时逐项核验该版本 API、addon 初始化与透射限制，不从新版本示例直接照搬未验证属性。本文件的具体造型与工作顺序是基于项目的设计方案，不是官方规范。
